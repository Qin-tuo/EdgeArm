# 扩展业务流程与推理后端

新增业务优先实现 Processor，而不是修改 Executor。完整且可编译的数值示例见 [custom_pipeline.cpp](../examples/custom_pipeline.cpp)，它只链接核心库。

## 添加处理器

1. 在自己的模块中实现 `describe()` 和 `process(Packet&, Context)`，或使用 `FunctionProcessor`。
2. 约定输入和输出字段的名字、类型与格式，并在模块入口校验。推理输入的采样率、张量布局和 Tokenizer 都是模块契约。
3. 在应用装配中调用 `Registry::add` 注册工厂；工厂读取对应配置节，拒绝未知后端。
4. 将处理器名字加入配置的 `pipeline.stages`，并明确它与前后阶段的字段依赖。
5. 为长计算和流式回调添加 `checkpoint`；成功才输出可消费的结果。用行为测试验证取消后不会执行下游，以及失败后下一任务可运行。

需要新的 Payload 类型时，先判断现有字节向量或 float 向量是否够用；跨多个业务共享的新类型再进入核心。业务特有的会话历史、动作请求和输入协议留在模块中。

## 接入真实推理库

真实后端通过同一处理器接口接入，但不要求不同模型拥有相同的张量形状。处理器内部拥有模型实例与 SDK 资源，并处理加载、释放、输入映射、流式状态和错误转换。SDK 头文件只出现在适配器的实现或内部头文件中。

可新增 `rvs_adapter_sherpa`、`rvs_adapter_llama`、`rvs_adapter_rknn` 或 `rvs_adapter_rk1828` 目标，由对应选项显式启用。依赖缺失时给出清楚的配置错误；默认构建不拉取大型源码、权重或设备工具链。把真实后端注册为独立配置值，不能沿用 mock 标签。

当前没有这些适配器，也没有对应的有效构建开关。新增适配器时再实现其 CMake 查找、版本固定和链接步骤，避免一个空开关被误认为完成了接入。

模型和数据采用 `tools/assets/register.py` 登记文件大小、SHA256、来源与声明的许可。工具只记录声明，不判断训练或分发权限。正式部署需要补充模型精度、前后处理、词表、转换命令和验证结果。

## 改变应用目标

若目标改为文本任务，采用 echo 配置作为入口；若改为视觉或其他数值任务，可采用数值示例的 Packet 与 Processor 方式。核心库不需要包含新业务名称。应用需要网络或进程通信时，新增独立 I/O 模块，保持外部协议与内部 Packet 的转换边界。

顺序流水线满足第一版的可运行与可测试需求。只有真实任务需要分支、并发或流式重叠时，再新增调度器。复用 Context 的取消与截止时间语义，定义队列容量、消息归属与完成事件后再实现，并用压力与取消测试验证。
