# 陪伴机器人端侧语音项目任务拆解

配套执行安排见[实施计划书](project-plan.md)，包含逐项工时、阶段门槛、相对周排期和验收证据。本清单中的历史环境记录需在启动阶段重新核验。

当前目标已调整为[通用工程框架](architecture.md)。以下任务清单保留为语音方向的候选拆解，暂不按硬件与训练阶段推进。

本计划将原任务书拆成有依赖和验收条件的工程任务。先在 RK3588 上完成离线 CPU 参考闭环，再验证 RKNN 和 RK1828 的可用路径，最后完成公开数据适配、异构集成和性能优化。模型与后端选择由设备测试决定。

根据本次用户要求，训练与离线评测优先使用网上公开数据集，自采训练录音不再作为前置条件。真实房间中的距离、回声、打断和长时间运行仍需实机测试；合成音频测试单独报告。

## 公开数据方案

| 用途 | 首选来源 | 首轮规模与处理 | 使用边界 |
| --- | --- | --- | --- |
| ASR 基线与适配 | [AISHELL-1 官方页面](https://www.openslr.org/33/) | 先固定小型评测子集；适配从训练集选择约 10–20 小时，按资源逐步扩大 | 官方标注 Apache 2.0；这是安静室内录音，不能代替真实远场评测 |
| TTS 适配 | [AISHELL-3 官方页面](https://www.openslr.org/93/) | 选择 1–3 名说话人的合格录音，按实际可用时长建立小规模实验 | 官方标注 Apache 2.0；训练音色与现有基础模型的说话人机制需匹配 |
| 噪声增强 | [MUSAN 官方页面](https://www.openslr.org/17/) | 选择噪声子集，先做固定信噪比的离线对照 | 官方标注 CC BY 4.0；记录来源、署名、修改和子集清单 |
| 多轮对话适配候选 | [BELLE Multiturn Chat 0.8M 数据卡](https://huggingface.co/datasets/BelleGroup/multiturn_chat_0.8M) | 清洗后选择约 1000–5000 个对话，完成轻量 SFT 或 LoRA 对照 | 数据卡另有限研究用途、禁止商业使用条款；含未严格核验的合成回答，暂不默认纳入部署模型 |
| 系统任务评测 | 项目独立编写的场景集 | 覆盖多轮记忆、澄清、取消、无语音、识别失败和动作白名单 | 训练集与验收场景分离，固定版本；不把数据集参考回答当作动作权限 |

AISHELL-1、AISHELL-3、MUSAN 官方归档分别标注约 15GB、19GB、11GB。选择子集不一定能避免整包下载；实施下载工具前先核对归档布局、解压空间、校验信息与服务器是否支持恢复下载。根据存储预算分批处理，不同时保留全部归档、解压副本和增强副本。

数据集与基础模型的许可分别记录。BELLE 候选需完成适用性核对再决定是否使用；其标签不能代替数据卡的额外条款。项目代码、数据和模型产物的分发范围分别说明。

数据处理要求：

- 固定来源、修订版本、下载地址、许可快照、校验值和随机种子；大文件放在仓库之外。
- ASR 优先保留官方切分，适配和增强只使用训练部分；同一原始录音的全部衍生样本属于同一集合。
- ASR 的音频接口先统一为单声道 16kHz；TTS 使用所选模型要求的采样率，通过明确的重采样边界连接播放端。
- TTS 已知说话人适配按场次和文本隔离训练与测试；若评测未见说话人，另设说话人隔离实验，分别报告。
- 对话数据按完整会话和重复内容分组后切分，过滤角色格式错误、无效回答和虚构动作执行结果。
- 记录基础模型公开的预训练数据范围。项目测试集未参与本次适配，不等于可以证明它未参与基础模型预训练。
- 合成噪声、模拟混响、真实房间测试分别标记；实际距离与回声测试不能由加噪结果推断。

## 验收与测量规范

| 指标或行为 | 统一规则 |
| --- | --- |
| 端到端首音响应 | 用户实际语音结束至扬声器输出首段有效回答语音；单独记录端点检测等待 |
| ASR | 固定文本规范化和解码参数，报告 CER、分层质量、RTF 与延迟分位数 |
| LLM | 记录上下文长度、输入输出 token 数、首 token 时间与生成速度；多轮完成率用固定场景判定 |
| TTS | 分开记录首音频产生与实际可听时间，报告 RTF；人工可懂度和自动转写代理指标分别标明 |
| 打断 | 用户开始打断至实际停止播放；检验恢复收音及旧轮次结果清理 |
| 延迟分位数 | 固定输入、明确预热与冷启动；报告样本数、原始数据、P50/P95 和失败率，不能静默丢弃失败样本 |
| 跨后端比较 | 固定模型、数据与前后处理；线程、频率、精度、温度和工具链分别记录 |
| 资源与功耗 | 记录指标来源、采样频率与可测范围；无硬件计数器或功耗仪时标记未测量 |
| 30 分钟稳定性 | 明确交互脚本、阶段重叠和并发强度，记录内存增长、温度、延迟变化及恢复次数 |
| 动作接口 | 正常请求按白名单执行；未知动作、非法参数和被取消轮次均不能触发动作 |

任务 12 完成后冻结性能目标和质量容差，并在加速对照前写入配置。首版至少完成 20 个固定多轮场景；自动化结果与实际收音测试分别记录。实时语音负载以 ASR/TTS RTF 小于 1 为目标，若不满足则继续定位瓶颈，并在最终结果中明确未达标项。

单模型测试建议预热后至少 100 次测量；完整交互建议至少 100 轮并包含正常、打断和恢复场景。实际耗时较长时可分批执行，但保留统一配置及每批条件，报告样本数。性能优化必须同时评估质量与失败率。

## 阶段工时与里程碑

沿用原任务书的估时区间，调整转换验证与训练的顺序。以下为规划工时，不是承诺；阶段 0 后按真实 SDK、音频和训练条件更新。

| 阶段 | 对应工作 | 工时 | 里程碑 |
| --- | --- | ---: | --- |
| 0 环境核验 | 00–03 | 15–25h | 硬件、SDK、音频与存储路径明确 |
| 1 CPU 参考闭环 | 04–12 | 20–30h | 断网条件下完成一次完整语音交互 |
| 2 转换与部署验证 | 13–14、18 的基础模型部分 | 40–65h | 明确各候选后端可用性并固定模型 |
| 3 数据与适配 | 15–17、18 的适配模型部分 | 55–85h | 有可复现训练与质量对照，或按条件记录受阻项 |
| 4 异构系统集成 | 19–21 | 40–60h | 多轮、打断、恢复与动作接口可用 |
| 5 Profiling 与优化 | 22–23 | 45–70h | 至少一项有证据的优化完成 |
| 6 稳定性与呈现 | 24–26 | 30–45h | 实机结果与作品集可复现 |
| 合计 | 另加 5–10h 硬件差异预留 | 250–390h | 完整版交付 |

公开数据可减少自行采集和标注，但会增加下载、清洗与格式适配工作，暂不据此缩减总工时。RK1828 核验设定阶段 0 的投入上限；支持不足时按任务书降级，不无限延长。

## 首批执行任务

先执行 00–03：保存环境报告、配置 /userdata 存储、完成真实录放检查、核验可用 SDK 示例。随后建立工程骨架和固定输入集，完成 WAV 输入到回答音频输出，再接入实时麦克风。第一里程碑交付 CPU 离线参考闭环及阶段计时，不以训练任务作为前置条件。

需要现场配合的部分包括麦克风与扬声器的实际连接、真实房间听音和距离测试，以及提供可访问的 RK1828 配套环境和 CUDA 工作站。代码、数据工具、实验配置、自动化测试和文档可在可访问的环境中完成。
